# Dataset Documentation

## 1. Datasets considered

| Dataset | Content | Access / licence situation | Used? |
|---|---|---|---|
| **Celeb-DF (v1/v2)** (Li et al., CVPR 2020) | 590 real + 5,639 face-swap videos (+300 YouTube-real) | Request form + terms; non-commercial research | **No** - not obtainable here. The original prototype was trained on it (data not in the repo) |
| **FaceForensics++** (Rössler et al., ICCV 2019) | 1,000 real + manipulated videos (5 methods) | Signed terms-of-use form | **No** |
| **DFDC** (Dolhansky et al., 2020) | ~100k clips | Kaggle competition rules / Meta terms | **No** |
| **DeeperForensics-1.0** | 60k videos | Access request | **No** |
| Unofficial mirrors of the above on file-sharing hubs | - | Redistributed without the owners' agreement | **Deliberately not used** (would bypass access controls) |
| **DeepFakeFace (DFF)** (Song et al., arXiv:2309.02218) | 30,000 real photos (IMDB-WIKI subset) + 3 × 30,000 diffusion/face-swap fakes | Hugging Face `OpenRL/DeepFakeFace`, tag **openrail**, ungated | **Yes - a sampled subset** (below) |

No random internet images were used as ground truth. Ground truth in DFF is known **by construction** (real = original IMDB-WIKI photograph, fake = generated by a named tool from it).

## 2. What was actually used: a seeded DeepFakeFace sample
Fetched with `backend/training/fetch_deepfakeface.py` (HTTP range requests; only the sampled files were downloaded, never the 5 GB archives); seed 42.

| Generator | Method | Role |
|---|---|---|
| `wiki` | real photograph | real class (all splits) |
| `inpainting` | Stable Diffusion inpainting of the face region | fake, **seen** generators (train/val/test_internal) |
| `insight` | InsightFace face swap | fake, **seen** generators |
| `text2img` | Stable Diffusion v1.5 text-to-image | fake, **unseen** generator (only `test_crossgen`) |

Per sampled image path we keep the real image and **one** fake counterpart (balanced classes). Source names are identical across archives (`<wiki-page-id>_<dob>_<year>.jpg`), so the numeric prefix is the person identity.

| Split | Purpose | Generators | Identities | Images after validation (real / fake) |
|---|---|---|---:|---|
| `train` | fitting | inpainting, insight | 1,197 | 1,170 / 1,145 |
| `val` | early stopping, checkpoint selection | inpainting, insight | 249 | 239 / 232 |
| `test_internal` | final test, **unseen identities**, seen generators | inpainting, insight | 300 | 292 / 283 |
| `test_crossgen` | final test, **unseen identities and unseen generator** | text2img | 300 | 281 / 287 |

Raw sample: 4,100 files (2,050 pairs). MTCNN found no face in 163 images (kept out; counts per class/split in `backend/manifests/dff_validation_report.json`), and 8 images were removed as cross-split duplicates (below). Both manifests (`dff_raw_manifest.csv`, `dff_faces_manifest.csv`) with file hashes are committed; the images are not.

## 3. Pipeline
1. **Fetch** (`fetch_deepfakeface.py`): seeded identity-disjoint sampling; SHA-256 of every file.
2. **Faces** (`prepare_faces.py`): MTCNN largest face, margin 20, 224×224, saved as JPEG **quality 95** via OpenCV - exactly the storage format of the original training crops, and what inference reproduces.
3. **Validation** (`data_validation.py`, run automatically; the script aborts on leakage): identity-disjoint and pair-disjoint splits, exact (SHA-256) and near (64-bit difference hash, Hamming ≤ 4) duplicates, class and generator distribution, shortcut diagnostics.
4. **Train/eval datasets** (`dataset.py`).
Video datasets: `training/video_tools.py` builds **source-video / identity-grouped** manifests from a CSV and selects the video aggregation method on validation data only. It is unit-tested on synthetic inputs but **has not been run on a real video benchmark** (none was available).

## 4. Leakage prevention (checked, not assumed)
| Risk | Control | Result |
|---|---|---|
| Same identity in several splits | split by identity; `check_group_disjoint` on identity and pair id | **0 violations** |
| A real photo and its fake in different splits | pair = same identity ⇒ same split | 0 violations |
| Duplicate/near-duplicate images across splits | SHA-256 + difference-hash search; offending item in the later split is dropped | 4 exact pairs, 7 near pairs found; **8 cross-split pairs removed** |
| Test data used for model selection | selection (early stopping, best checkpoint) uses `val` only; thresholds are never fitted | by construction (`training/train.py`) |
| Same video frames across splits (video data) | group by source video / identity | implemented, untested on real video |

## 5. Shortcut / bias diagnostics (reported, not hidden)
AUC of a single scalar as a real/fake predictor (0.5 = no signal):

| Split | raw file size | crop JPEG size (q95) |
|---|---:|---:|
| train | 0.279 | 0.316 |
| val | 0.295 | 0.350 |
| test_internal | 0.249 | 0.341 |
| test_crossgen | 0.293 | **0.621** |

Fake files are consistently smaller than real ones (plausibly because generated images contain less high-frequency detail; the cause was not investigated), so *some* compression/size cue exists in the seen-generator splits. For the unseen generator the crop-size cue **reverses**, so it cannot explain cross-generator success. Mitigations: crops are re-encoded at one fixed quality, and training augments with random JPEG re-compression (q 60-95), blur and colour jitter. The cue is monitored through the JPEG-recompression robustness test in the evaluation report.

Other dataset limitations: real photos come from IMDB-WIKI (celebrities, frontal-ish, variable quality); fakes are *images*, not videos; no temporal artefacts; subjects are public figures (demographic bias is not characterised); the "real" class contains the web-image compression history of IMDB-WIKI.

## 6. Augmentation (training only; every transform documented)
Horizontal flip (p = 0.5) · colour jitter (brightness 0.1, contrast 0.1, saturation 0.05) · Gaussian blur k = 3, σ ∈ [0.1, 1.0] (p = 0.2) · extra JPEG re-compression, quality U[60, 95] (p = 0.5). No augmentation in validation/test/inference. The original prototype used none.

## 7. Privacy and redistribution
Images depict real, identifiable people (IMDB-WIKI) and generated likenesses. **No dataset images are committed to the repository**; example montages with faces are generated locally and git-ignored. Re-obtain the data with the documented scripts and respect the dataset licences and IMDB-WIKI's academic-use terms.

## 8. Reproduce
```bash
cd backend
python -m training.fetch_deepfakeface --out data/raw/dff --seed 42
python -m training.prepare_faces --manifest manifests/dff_raw_manifest.csv --name dff
```
The committed manifest hashes allow verifying that a re-download is byte-identical.
